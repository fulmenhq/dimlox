# dimlox v0.1.0

`dimlox` v0.1.0 is the first public release of the CLI for moving, inspecting,
and splitting large files across Azure Blob Storage, Google Cloud Storage, and
local filesystems without loading whole files into memory.

## Highlights

- Streaming transfer commands for `get`, `put`, and `cp`
- Streaming inspection commands for delimiter detection, row counts, and targeted samples
- Repeatable split workflows with manifests, dry-run planning, and atomic writes
- Provider-aware auth and discovery via `doctor` and `ls`
- Windows-aware local workflows and release artifacts
- GitHub Actions CI, cross-build, native smoke, and draft release automation

## Included in this release

### Provider and path support

- Azure Blob Storage via `azblob://...` and Azure HTTPS blob URLs
- Google Cloud Storage via `gs://...` and `storage.googleapis.com` URLs
- Local absolute, relative, and `file://` paths

### Core commands

- `doctor` checks auth state, connectivity, and targeted metadata probes
- `ls` lists containers, buckets, prefixes, and local paths
- `get` downloads to a local path with streaming progress and optional verification
- `put` uploads a local file to cloud or local storage
- `cp` copies between providers through a local landing file
- `inspect` streams delimiter detection, row counts, and head/mid/tail samples
- `split` creates stream, range, and binary shards with dry-run support and optional manifests

### Platform and workflow support

- Windows path-length preflight for `split`
- Atomic shard writes through `.part` files and rename-on-success behavior
- PowerShell-aware local build and test helpers
- Native smoke coverage on Linux and Windows arm64 runners
- Draft GitHub Release automation for `v*` tags, with local signing and provenance upload kept in maintainer workflows

## Operational notes

- Azure Blob auth uses `DefaultAzureCredential`, with optional named-profile selection through `--az-profile`
- Google Cloud Storage auth uses Application Default Credentials
- Progress output goes to `stderr`; non-TTY runs emit structured JSON Lines progress events
- Compressed cloud `inspect --mid` and `inspect --tail` operations require `--force-stream` because they need a full forward read

## Upgrade and installation notes

- Build from source with `make build` or install locally with `make install`
- CI produces draft release artifacts for Linux, macOS, and Windows
- Maintainer signing, public-key export, and provenance upload are documented in `RELEASE_CHECKLIST.md`

## Known constraints at release time

- The release workflow creates draft GitHub Releases; signing and provenance upload remain local maintainer steps
- `make lint` still reflects the broader repo lint backlog outside the release workflow scaffolding
