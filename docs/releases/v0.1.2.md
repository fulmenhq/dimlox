# dimlox v0.1.2

`dimlox` v0.1.2 is the first feature release after the initial public launch.
It adds multi-file copy, GCS profile support with per-leg auth for cloud-to-cloud
transfers, package manager distribution, and foundry-aligned exit codes.

## Highlights

- Multi-file `cp` with glob expansion, JSONL batch input, and positional multi-source
- GCS named profile support and per-leg auth for mixed-identity cloud-to-cloud copies
- Homebrew and Scoop distribution
- Exit codes aligned with the gofulmen foundry catalog
- Context-cancellation cleanup across all transfer paths

## Multi-file cp

`cp` now supports copying multiple files in a single invocation through three
input modes:

```bash
# Glob expansion (provider-side listing + client-side path.Match)
dimlox cp --dry-run "gs://bucket/data/orders_*.psv" "azblob://acct/container/archive/"

# JSONL batch file
dimlox cp --continue-on-error --from-file transfers.jsonl

# Positional multi-source
dimlox cp src1.psv src2.psv /tmp/out/
```

All modes use a plan → validate → execute pipeline. `--dry-run` prints the
transfer plan without executing. Validation catches destination collisions,
bad URIs, and missing trailing `/` before any I/O.

New flags: `--from-file`, `--dry-run`, `--continue-on-error`, `--max-sources`,
`--parallel` (reserved, currently only accepts `1`).

## GCS profile and per-leg auth

All commands now accept `--gcp-profile <name>` to select a named gcloud
configuration. For `cp`, per-leg flags allow different GCS identities on source
and destination:

```bash
dimlox cp \
  --gcp-profile-src project-a \
  --gcp-creds-file-dst /path/to/dest-service-account.json \
  "gs://source-bucket/data/orders.psv" \
  "gs://dest-bucket/data/orders.psv"
```

Per-leg credential precedence: `--gcp-creds-file-src/dst` > `--gcp-profile-src/dst`
> global `--gcp-profile` > process `GOOGLE_APPLICATION_CREDENTIALS` > default ADC.

`doctor --list-gcp-profiles` enumerates local gcloud configurations without
network calls.

A named profile changes ADC identity only when its config includes
`auth/credential_file_override`. Otherwise it contributes project and account
context only.

## Package manager distribution

```bash
brew install fulmenhq/tap/dimlox
```

```bash
scoop bucket add fulmenhq https://github.com/fulmenhq/scoop-bucket
scoop install fulmenhq/dimlox
```

Release maintainers: `make update-homebrew-formula` and `make update-scoop-manifest`
update the sibling tap and bucket repos after a published release.

## Exit code changes (breaking)

All exit codes now use the gofulmen foundry catalog. This is a breaking change
from v0.1.1 for scripts that check specific exit code values:

| v0.1.1 | v0.1.2 | Meaning |
|--------|--------|---------|
| `0` | `0` | Success |
| `1` | `1` | Generic runtime failure |
| `2` | `40` | Invalid argument or unsupported URI |
| `3` | `63` | Checksum mismatch (`--verify`) |
| `4` | `33` | Disk full (ENOSPC) |
| — | `70` | Authentication failed (new) |

Auth errors (GCS `ErrADCMissing`, Azure `AuthenticationFailedError`) now return
`70` instead of `1`. `doctor` auth probe failures also return `70`, useful for
CI preflight gates.

Batch `cp` with `--continue-on-error` returns the worst failure class:
auth (`70`) > data corrupt (`63`) > resource exhausted (`33`) > generic (`1`).

## Cancel cleanup

Context cancellation (Ctrl+C / SIGINT / SIGTERM) now cleans up partial state:

- Downloads remove the `.part` temp file
- Uploads remove compressed temp files
- `cp` removes the landing file (unless `--keep-landing`)

## Upgrade notes

- Update any shell scripts or CI pipelines that check exit codes `2`, `3`, or `4`
  to the new values (`40`, `63`, `33`)
- The `--parallel` flag is accepted but only `1` is supported; higher values
  return an error
- Per-leg GCS auth flags are `cp`-only; other commands use global `--gcp-profile`
